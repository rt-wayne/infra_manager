## 查證結果

### WPX VerifySecure API（來源：`D:\ai\secrets\WPX\ClientDelivery\VerifySecure-Client.md` v1.1，2026-10-06）

- 流程：`GET /VerifySecure/PublicKey` 取 `kid`＋WPX 公鑰（可快取一天，收到 -23 重取）→ 內層 `{"userid","pwd","ts","nonce"}` 以 WPX 公鑰 RSA-OAEP（SHA-1／MGF1 SHA-1）加密成 `cipher` → `appId|kid|ts|nonce|cipher|dbalias|machine|os|ip` 九欄以 `|` 串接，用本系統私鑰 RS256（SHA256withRSA）簽成 `sig` → `POST /VerifySecure/SignInGetToken`，`Code=0` 為成功
- 測試環境：appId＝`Test`（區分大小寫）、dbalias＝`APX`（測試與正式皆同）、內網 http；正式環境 WPX 會提供 HTTPS 位址。位址不記在 repo，見上述說明文件
- `ts` 為 UTC、與 WPX 相差 ±300 秒內 → UAT／正式主機要對 NTP；`nonce` 每次不同，重試要整包重產（同包重送回 -20）
- 建議 HTTP 逾時 10 秒
- 錯誤碼：0 成功；-18～-27 為加密／簽章／格式層錯誤（本系統程式或設定問題）；-1 查無使用者、-2 留職停薪、-3／-4／-5 鎖定、-6／-7 時段、-8～-10 分店或 IP、-11～-14 密碼錯（-13 首次登入密碼應等於員編）、-15 請改用員編
- 不需要新套件：JDK 內建 RSA／Signature／HttpClient，外呼寫法可比照 `DbConnectApiClient.java`（RestTemplate 自建、不印回應本文）
- 私鑰只放後端伺服器：不進 jar、不進版控、不寫 log；使用者密碼加密後不留存
- 測試金鑰指紋已核對（2026-10-20）：`pxgo.public.pem` 的 SHA-256 為 `1F77 1827 … 0698 FB5F`，與 WPX 信件一致；`pxgo.private.pkcs8.pem` 與之同一對
- 正式上線：本系統自行產生 RSA-2048 金鑰對，只把公鑰與指紋交 WPX 登錄、雙方另管道核對；正式 appId、位址由 WPX 通知

### PX_SYNC 三張表（2026-10-20 測試 DB `itflow_uat` 以 AP_USER 實查）

- `PX_SYNC_EMP`（同步人員檔）：`EMP_ID` VARCHAR2(30) 主鍵（型別同 `IM_ACCT_USER.USER_ID`）、`EMP_NAME` VARCHAR2(120)、`EMAIL` VARCHAR2(100)、`STATUS`（註解：**資料列狀態，非業務狀態**——不代表在職）、CREATE_／UPDATE_ 四欄。**沒有英文名、分機、在職狀態欄**
- `PX_SYNC_DEPT_EMP`（同步單位人員檔）：主鍵 `DEPT_ID＋EMP_ID＋IS_MGR`；`IS_MGR` 1＝主管、0＝成員
- `PX_SYNC_DEPT`（同步單位檔）：`DEPT_ID` 主鍵、`DEPT_NAME`、`DEPT_FULL_NAME`、`UP_DEPT_ID` 等
- 筆數：EMP 53,810、DEPT_EMP 40,620、DEPT 3,724，全部 `STATUS=1`
- **同步方式線索**：EMP 與 DEPT_EMP 全部 `CREATE_DATE` = 2026-10-20 04:59、`UPDATE_DATE` 全空 → 推測每日整表清空重灌（也可能當天首次建立）。**待確認**：隔天再查，CREATE_DATE 全變隔天即確認
- 資料品質：`EMP_NAME` 無空值、最長 30 字；`EMAIL` 53,810 筆中只有 8 筆有值（測試 DB）；14,008 人沒有任何有效部門列（INNER JOIN 部門會整個查不到）；320 人有多個有效部門列（303 人不同部門、17 人同部門主管兼成員）；部門顯示名最長 28 字（本系統 `DEPT_NAME` 50 CHAR 放得下）；部門全名欄有字串 `'NULL'`（非真空值）
- 本系統 13 位使用者全在 PX_SYNC_EMP 找得到；姓名 13 位全一致；Email 全不一致（對方為空）；部門 11 位一致，0000285 本系統「資訊處」對方「資訊部」，0121178 對方是兩個子單位
- 使用者提供的參考 SQL（2026-10-20）：`PX_SYNC_EMP e JOIN PX_SYNC_DEPT_EMP de（STATUS=1）JOIN PX_SYNC_DEPT d（STATUS=1）WHERE e.STATUS=1 AND NVL(d.DEPT_FULL_NAME, d.DEPT_NAME) LIKE '%資訊部%'`，取工號、姓名、Email、部門代碼、部門、主管。照用會有：多部門者多列、無部門者查不到、字串 'NULL' 漏網三個問題（⑪ 已定處理方式）
