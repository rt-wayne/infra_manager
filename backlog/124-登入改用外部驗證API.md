## 查證結果

### WPX VerifySecure API（來源：`D:\ai\secrets\WPX\ClientDelivery\VerifySecure-Client.md` v1.1，2026-10-06）

- 流程：`GET /VerifySecure/PublicKey` 取 `kid`＋WPX 公鑰（可快取一天，收到 -23 重取）→ 內層 `{"userid","pwd","ts","nonce"}` 以 WPX 公鑰 RSA-OAEP（SHA-1／MGF1 SHA-1）加密成 `cipher` → `appId|kid|ts|nonce|cipher|dbalias|machine|os|ip` 九欄以 `|` 串接，用本系統私鑰 RS256（SHA256withRSA）簽成 `sig` → `POST /VerifySecure/SignInGetToken`，`Code=0` 為成功
- 測試環境：appId＝`Test`（區分大小寫）、dbalias＝`APX`（測試與正式皆同）、內網 http；正式環境 WPX 會提供 HTTPS 位址。位址不記在 repo，見上述說明文件
- `ts` 為 UTC、與 WPX 相差 ±300 秒內 → UAT／正式主機要對 NTP；`nonce` 每次不同，重試要整包重產（同包重送回 -20）
- `machine`、`os` 兩欄文件寫「記錄用，可為空字串」：填主機名稱與作業系統即可，不影響驗證
- 建議 HTTP 逾時 10 秒（殼 jar 轉送讀取逾時 120 秒，不會先斷線）
- 錯誤碼：0 成功；-18～-27 為加密／簽章／格式層錯誤（本系統程式或設定問題）；-1 查無使用者、-2 留職停薪、-3／-4／-5 鎖定、-6／-7 時段、-8～-10 分店或 IP、-11～-14 密碼錯（-13 首次登入密碼應等於員編）、-15 請改用員編
- 不需要新套件：JDK 內建 RSA／Signature／HttpClient，外呼寫法可比照 `DbConnectApiClient.java`（RestTemplate 自建、不印回應本文）
- 私鑰只放後端伺服器：不進 jar、不進版控、不寫 log；使用者密碼加密後不留存；WPX 回應、`cipher`、`sig` 也不寫 log，只記工號與 WPX 原始 Code
- 測試金鑰指紋已核對（2026-10-20）：`pxgo.public.pem` 的 SHA-256 為 `1F77 1827 … 0698 FB5F`，與 WPX 信件一致；`pxgo.private.pkcs8.pem` 與之同一對
- 正式上線：本系統自行產生 RSA-2048 金鑰對，只把公鑰與指紋交 WPX 登錄、雙方另管道核對；正式 appId、位址由 WPX 通知
- **交付包沒有測試帳號、也沒有窗口聯絡方式**（2026-10-20 檢查）：文件寫「測試帳號由 WPX 窗口另行提供，不隨本文件寄送」，窗口欄是「（請填）」
- **開發機通路已驗證**（2026-10-20）：`GET /VerifySecure/PublicKey` 成功（kid＝`2026-10`）；以交付包 PowerShell 腳本、測試私鑰、appId＝`Test`、假工號送 `SignInGetToken` 回 **Code -1（查無使用者）**＝加密與簽章通過、測試公鑰已在 WPX 登錄。UAT 主機未從開發機驗證
